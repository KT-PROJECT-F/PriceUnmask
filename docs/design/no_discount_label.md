# Proposal: no-discount Trust Score label

## Status

Proposed design for review. No implementation changes are included in this proposal.

## Context

The current Trust Score uses four labels:

- `genuine`
- `uncertain`
- `likely_inflated`
- `insufficient_data`

In `backend/analysis/trust_score.py`, `claimed_discount_pct` is calculated from the latest snapshot's `original_price_minor`. If that value is absent, the claimed discount is `None`. The current scoring rules can still return a score of 100 and the `genuine` label when no strong warning signals are detected.

However, absence of a recorded discount is not proof that a discount is genuine. The label should communicate whether the available data supports judging an advertised discount.

## Evidence from the Trust Score findings

The findings report for `priceunmask-20261019.db` analyzed 20 of 20 products and 800 snapshots. None of the analyzed products had a recorded original price, and all 20 received score 100 and label `genuine`.

This dataset shows a gap in interpretation: a high score may reflect a lack of warning signals rather than evidence that a discount claim is genuine. The report recommends considering a neutral label for insufficient discount evidence.

## Proposed rule

Introduce a separate label, `no_discount`, displayed to shoppers as **No discount to judge**.

Classification decision:

- Histories with fewer than the existing minimum of six snapshots remain `insufficient_data`.
- With six or more snapshots, assign `no_discount` when the latest snapshot has no valid discount claim.
- A valid discount claim is a snapshot where `original_price_minor` is present, positive, and strictly greater than `current_price_minor`. Missing, zero, lower, and equal original prices do not qualify; equal prices represent a 0% discount.
- If the latest snapshot has a valid claim, use the existing Trust Score evaluation.

**Why the latest snapshot only:** `compute_signals` uses only the latest `original_price_minor` for `claimed_discount_pct`, and `spike_before_discount` needs that latest claim. An older claim does not change the score: in an eight-snapshot stable-price test, the history with an older claim and the history with no claim both returned score `100` and label `genuine`. Treating them differently would give two products with identical signals different labels. The shopper is judging today's advertised discount, so the rule looks at today's snapshot.

**Implementation note:** `compute_signals` currently allows `original_price_minor >= current_price_minor` when calculating `claimed_discount_pct`, while the `claimed_sale` signal uses strict `>`. Implementation should align these checks with the proposed rule so equal prices are not treated as a discount.

## Proposed score and shopper-facing copy

* API label: `no_discount`
* Display label: `No discount to judge`
* Score behavior: `no_discount` always has a `null` score. Do not return `100` or another numeric score for this classification: no discount claim exists in the available history to assess. This is distinct from `insufficient_data`, which also has a `null` score because there are too few snapshots to evaluate.
* Shopper-facing message: "No discount to judge. The latest price has no discount to evaluate."
* Approval: The shopper-facing wording was approved by @lakshmiprasanna45 on 2026-10-26.

The classification and `null` score behavior are the proposed contract for implementation. The approved shopper-facing wording should be used consistently in the API response and dashboard.


## Demo product impact

The frontend mock files (`frontend/mock/history-*.json`) contain 21 snapshots per product, from 2026-09-17 through 2026-10-07.

| Product | Observed history | Expected outcome under the proposed rule |
|---|---|---|
| Demo Bluetooth Speaker (ID 1) | Original price of 219900 minor units is recorded; latest price is 179900. | Keep existing scoring path; not `no_discount`. |
| Demo Running Shoes (ID 2) | Original price of 349900 is recorded; latest price is 279900. | Keep existing scoring path; not `no_discount`. |
| Demo Air Fryer (ID 3) | Latest price is 104900 and latest original price is 349900; earlier snapshots include prices without an original price. | Keep existing scoring path; not `no_discount`. |

These are mock-data observations, not a claim that the demo scores have been recalculated. The currency in these mock files is INR and the prices are stored in minor units.

The seeded products generated by `backend/devtools/seed_fake_data.py` were validated using a fresh temporary database (`data/exports/seeded-review-check.db`) and `python -m backend.devtools.trust_score_report`. The report analyzed 3 products and 378 snapshots (126 per product). All three products had at least one recorded original price; two were labeled `genuine` (score 100 each), and the Demo Air Fryer was labeled `likely_inflated` (score 20). The seed definitions also contain valid discount claims for all three products. Therefore, this seeded dataset does not provide a no-discount example for testing the proposed classification.

## Test-case proposal

| History scenario | Expected label | Expected score |
|---|---|---|
| Fewer than six snapshots | `insufficient_data` | `null` |
| Six or more snapshots; latest snapshot has no valid discount claim (missing, zero, lower, or equal original price) | `no_discount` | `null` |
| Older valid claim exists, but the latest snapshot has no valid claim | `no_discount` | `null` |
| Valid discount claim in the latest snapshot, including histories with suspicious price movement | Existing scoring path, including current warning rules | Calculated by existing rules |
